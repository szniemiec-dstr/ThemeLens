ThemeLens

A window you place over anything on your screen. Whatever is underneath is shown in the colours you chose: a black page with soft off-white text, high contrast, reds and greens you can tell apart, or less blue in the evening. Clicks and typing go straight through to the app below.

1Summary

Many apps and web pages ignore the system theme. For someone with light sensitivity, low vision or red–green colour blindness, one bright white window can make the whole computer hard to use. Windows offers global colour filters and a magnifier, but nothing that maps arbitrary app colours onto a chosen theme.

ThemeLens is a topmost, click-through window. It captures what is underneath it, works out which colours are the background, the text and the accents, and redraws the same content in the user's theme. The lens can be a movable rectangle or fill one screen.

The one rule that outranks every other. Inside the lens, the background is always the one the user chose. If the app cannot keep up, loses the capture, or is unsure, it shows the plain theme background rather than risk one bright frame on a dark theme.

The project is open source under GPL-3.0-or-later (section 12). Two points are still open before the repo starts: Windows 11 as the only first platform (section 3), and the name.

These needs overlap, so a theme is a combination of settings (base, contrast, brightness limit, warmth, colour-blind remap), and the built-in themes are just good starting combinations.

Wording in the app and on the website describes what the theme does to the screen. It makes no medical claims about migraine, sleep or eye health.

3Scope and assumptions

3.1Goals for version 1

  • A lens window that sits above other apps, recolours what is under it, and passes all mouse, touch, pen and keyboard input to the apps below.
  • Two lens shapes: a movable, resizable rectangle, and “fill this screen” on any one monitor.
  • Live colour analysis: find the main colour clusters under the lens and map them onto the theme's roles.
  • A control window that shows the detected colours and how each is mapped, and lets the user correct a mapping.
  • A first-run choice that starts with one question: dark or light.
  • A Passthrough theme that changes nothing, and optional contrast and sharpen settings on every theme.
  • One-click installer, no administrator rights, automatic updates.
  • Clone, open in VS Code, press F5, it runs.
  • A test suite in which the colour rules are executable specifications (Reqnroll).

3.2Not in version 1

  • macOS and Linux. The colour engine is written without Windows dependencies so it can be reused, but capture and overlay are different work on each system.
  • Understanding content: the lens does not know a photo from a button. Photos under a dark theme are recoloured like everything else (see risks).
  • Theming the lock screen, the UAC prompt, or exclusive full-screen games.
  • Several lenses at once, per-app profiles, schedules. These are planned follow-ups.

3.3Assumptions

  • Windows 11 is the only platform for the first release.
  • When the lens cannot show a picture it trusts, it fills with the theme's page colour: black on dark themes, the paper colour on light ones.
  • A hardware GPU is expected but not required. Without one the lens still works, more slowly (7.6).

4UX design and wireframes

4.1Principles

  • Background first. The chosen background colour is on screen before anything else and stays when things go wrong.
  • No flashes. Every change of theme or mapping is a short fade that moves straight to the target brightness. Nothing overshoots.
  • One question at a time. First run asks dark or light, then offers themes. Everything else has a sensible default.
  • Never colour alone. Every colour in the app's own UI has a name and a hex value next to it, so the control window is usable with any colour vision.
  • Always a way out. One shortcut turns everything off instantly. The lens handle is always visible while the lens is on.
  • The app follows its own theme. Installer splash, first-run window and control window open in the user's base, with black as the default before a choice exists.

4.2First run: choose a base

The first window has three large choices. Dark and Light change the background. “Keep my colours” leaves backgrounds alone, for someone who only wants red–green help, less blue, more contrast or sharper text. It is also where the Passthrough theme lives.

4.5Moving, resizing and filling a screen

A window that passes every click through cannot be dragged by its body, so the lens has two states.

  • “Fill this screen” snaps the lens to the full bounds of the monitor it is mostly on, including the taskbar. The same command again restores the previous rectangle.
  • With several monitors, the control window lists them by number and position (“Screen 2, right”). The lens covers one at a time in version 1.
  • The lens remembers its last rectangle and mode per monitor layout.
  • While moving or resizing, any part of the lens for which there is no fresh picture yet shows the theme background.

4.6Control window

The control window is an ordinary window, shown above the lens and never recoloured by it, so the “found” swatches show true screen colours.

The window also holds a Settings page (shortcuts, start with Windows, updates, language) and an About page (version, licence, third-party notices). The tray icon repeats the most common actions: lens on or off, theme, fill this screen, open control window, quit.

4.7Keyboard shortcuts

Defaults must not use Ctrl+Alt. On Polish and many other European keyboards Ctrl+Alt is the same as AltGr, so Ctrl+Alt+L would block typing “ł”. The proposed defaults use Win+Alt; each is checked at startup, and any that Windows or another app already owns is shown as “not set” for the user to choose.

4.8Accessibility of the app itself

  • Every control reachable and operable by keyboard, with a visible focus outline at least 3 px thick.
  • Every control has a UI Automation name and role, so Narrator and NVDA can drive the whole app. Changes of state (“Lens on, Soft dark”, “Holding background”) are announced.
  • Click targets at least 44 by 44 px at 100% scale. The UI follows the Windows text-size setting up to 225% without clipping.
  • The app's own UI passes 7:1 text contrast in every built-in theme.
  • No animation longer than 250 ms, none at all when Windows has animations turned off.
  • No sound, no toast notifications by default.

5.4Contrast and sharpen

Every theme, Passthrough included, has two optional settings. Both are off in the built-in themes, and the control window remembers the user's values per theme.

SettingRangeModesWhat it does
ContrastOff, or 1 to 100%Standard, LocalStandard pushes light and dark further apart across the whole lens. Local also lifts faint detail against its immediate surroundings, such as grey text on a grey panel.
SharpenOff, or 1 to 100%Standard, StrongMakes the edges of text and lines crisper. Strong uses a wider area and suits small or blurry text.

Local contrast and Strong sharpen are the heavier modes. They are allowed to exceed the standard performance budgets (7.6). Neither setting can break a theme's limits: the result is always clamped to the brightness limit and the page colour.

5.5Theme file

Themes are JSON files, validated against a published schema. Built-ins ship as files in themes/; user themes live in %AppData%\ThemeLens\themes. A theme is data only and cannot run code. contrast and sharpen are optional; leaving them out means off. Passthrough is a theme file with "base": "keep" and no roles.

6Colour engine

The engine is split in two so that slow work never delays a frame. Recolouring each pixel is a single table lookup on the GPU, every frame. Deciding what the table should contain happens on the CPU a few times a second.

6.1Finding colour clusters

  1. A copy of the lens area is shrunk on the GPU to about 160 by 90 pixels and read back, 5 to 10 times a second, and immediately after a large change in average brightness.
  2. Pixels are converted to OKLab, a colour space where equal distances look roughly equally different.
  3. A coarse 3D histogram finds the peaks. K-means, seeded from those peaks with at most 8 clusters, refines them. Clusters closer than a small threshold are merged.
  4. Each cluster gets features: share of area, lightness, chroma, hue, how much of it touches the lens edges, and how “thin” it is (text and lines have a lot of edge per pixel).
  5. Small clusters are kept if they are strongly coloured, since links and status dots cover little area but matter.

6.2Assigning roles

  • Page: largest share, low chroma, touches the edges.
  • Text: highest contrast against Page among thin clusters.
  • Panel and Quiet text: remaining low-chroma clusters, split by which side of the midpoint between Page and Text they fall on.
  • Link, Good, Warning, Bad: chromatic clusters by hue family (blue, green, yellow-orange, red).
  • Anything else becomes Other accent.

The user can override any row in the control window. A pinned row wins over the automatic choice until “Reset mapping”.

6.3Building the lookup table

The engine builds a 33×33×33 table that gives an output colour for every possible input colour, so colours that belong to no cluster (anti-aliased text edges, gradients, photos) are still handled smoothly.

  • Lightness follows one monotonic curve through the anchor pairs (source Page to theme Page, source Panel to theme Panel, source Text to theme Text). Because the curve never reverses, text edges stay smooth.
  • Hue and chroma: near-grey inputs take the theme's neutral tint. Coloured inputs are pulled towards the theme colour of the nearest accent cluster, weighted by distance, so in-between colours blend.
  • Limits are applied last: maximum luminance, minimum contrast for text-like lightness, maximum chroma, then the warmth and colour-vision transforms.

A table has about 36,000 entries and is built in a few milliseconds. The shader samples it with interpolation.

6.4Keeping the picture steady

  • A cluster must win a role in three analyses in a row before the role changes.
  • When the table changes, the shader cross-fades from the old one to the new one over 150 to 250 ms.
  • Average lens brightness may only move towards its target during a fade.
  • Pinned mappings never change on their own.

6.5Background first

The table is built from what was on screen a moment ago. If the user switches from a white document to a dark editor, a table that inverts lightness would, for a few frames, turn the dark editor white. That is exactly what a light-sensitive user must never see, so there are three protections, all of which work without waiting for the analysis.

ProtectionWhen it actsHow
Polarity checkSame frameThe GPU reduces each frame to a handful of average values. The shader uses them to choose between two ready tables: one for light sources, one for dark sources.
Area guardSame frameFor each pixel the shader also looks up the average colour of its neighbourhood. If that average would come out brighter than the theme allows, it is a background area and not text, and the pixel is pulled to the Page colour. On light bases the test is mirrored.
HoldWithin one frame of a faultIf capture fails, the display changes, or the render loop misses its deadline, the lens presents a solid Page fill and the status changes to “Holding background”.

“Keep background” in the control window sets how hard the area guard works. Strict never lets a large bright area through on a dark theme, which also flattens bright photos. Balanced allows areas that look like images (many colours, soft edges). Off disables the guard.

The lens is opaque, so pixels from the real desktop cannot leak through it. Delay can make the lens content lag by a frame, but it cannot show the unthemed screen.

6.6Red–green assist and less blue

  • Red–green assist does not restore colour vision. It moves differences that sit on the red–green confusion axis onto lightness and the blue–yellow axis, and it maps the Good and Bad roles to a pair that stays distinct under simulated protanopia and deuteranopia. Tests use the Machado, Oliveira and Fernandes (2009) simulation matrices.
  • Less blue scales the blue channel in linear light and slightly lowers green, which is equivalent to moving the white point towards warm. Text lightness is then corrected to hold the theme's minimum contrast.

6.7Contrast and sharpen

Setting and modeHow it is doneCost
Contrast, StandardSteepens the lightness curve around the midpoint between Page and Text. On the Keep base, around the median lightness of the picture. The curve stays monotonic and is baked into the lookup table.None per frame
Contrast, LocalCompares each pixel's lightness with a blurred copy of the frame and amplifies the difference.One blur pass plus one extra pass
Sharpen, StandardFive samples per pixel, on lightness only so no colour fringes appear. Strength falls where an edge is already crisp.One extra pass
Sharpen, StrongA wider two-pass kernel with halo limiting.Two extra passes

Order within a frame: recolour, local contrast, sharpen, then clamp to the theme's limits. Clamping last is what guarantees that sharpening halos on a dark theme can never exceed the brightness limit.

7.3The lens window on Windows

  • Click-through and topmost. A borderless popup with the extended styles WS_EX_LAYERED, WS_EX_TRANSPARENT, WS_EX_TOPMOST, WS_EX_NOACTIVATE and WS_EX_TOOLWINDOW. Hit-testing skips it, so mouse, wheel, touch, pen and drag-and-drop reach the window below. It never takes focus, so the keyboard is unaffected.
  • Drawing. A Direct3D 11 flip-model swap chain attached through DirectComposition (WS_EX_NOREDIRECTIONBITMAP), cleared to the Page colour before the window is first shown.
  • No feedback loop. The lens, handle and control windows call SetWindowDisplayAffinity with WDA_EXCLUDEFROMCAPTURE, so the capture sees the desktop as if they were not there. A side effect to document for users: screenshots and screen sharing show the original, unthemed screen.
  • Capture. Primary: Windows.Graphics.Capture on the monitor under the lens, with the cursor and the capture border turned off. Fallback: DXGI Desktop Duplication. Both sit behind one IFrameSource interface, chosen at run time.
  • Handle and edit mode. The handle is a second small topmost window without the transparent style. Edit mode removes WS_EX_TRANSPARENT from the lens until the user finishes.
  • DPI. Per-monitor DPI awareness v2. The lens rectangle is stored in physical pixels per monitor.

7.6Performance budgets

Budgets depend on what the user has switched on and on the hardware. Three tiers apply.

  • Standard: hardware GPU, with contrast and sharpen off or in Standard mode.
  • Heavier options: hardware GPU, with Local contrast or Strong sharpen on.
  • CPU only: no usable GPU, for example a basic display driver, some virtual machines and some remote sessions. The same shader runs on Windows' software rasteriser.

Outside the Standard tier the budgets are targets, and missing them is not a defect. The rules that keep the lens safe are not budgets and never relax: background first (FR-10 to FR-12), no flashes (FR-13) and click-through (FR-02, FR-03) hold in every tier.

  • The app never switches an option off by itself. When the lens runs past the Standard budget the status pill reads “Live, reduced speed”, and the control window names the option that costs most and offers one button to return to Standard modes.
  • On a CPU-only machine the heavier modes start off. The user can still turn them on.
  • A slow frame is always a complete frame: the lens shows the previous finished picture until the next one is ready, never a half-processed one.

7.7Platform limits to design around

  • Turning off the capture border needs build 20348 or later, which in practice means Windows 11. On older systems the fallback capture path is used.
  • Excluding a window from capture needs Windows 10 version 2004 or later. Older versions are not supported.
  • Windows shows some surfaces above every normal topmost window: Start, notifications, the lock screen and the UAC prompt. They appear unthemed. A later, separately installed build with the uiAccess manifest flag can go above most of them, but that requires a signed app installed for all users.
  • Protected video is captured as black. Exclusive full-screen games bypass the compositor.
  • Screen capture can be blocked by Windows privacy settings or by an organisation's policy. The app must detect a refused capture and say so plainly.
  • No hardware GPU: rendering falls back to the software rasteriser (CPU-only tier in 7.6). M0 confirms that screen capture works in this configuration.
  • HDR displays: version 1 processes in SDR. On an HDR desktop the lens area is tone-mapped to SDR, and the control window says so.

9.4Making it hard to break

  • CI runs build, Core tests and Specs on Windows and Linux for every pull request; Platform tests on Windows.
  • Line coverage of Core at least 90%. Mutation testing on Core weekly, with a floor that only goes up.
  • Golden images for each theme and fixture pair, compared with a perceptual tolerance, so an unintended colour change shows up as a diff a reviewer can look at.
  • A benchmark job tracks table build time and reference-render time and fails on a 20% regression. GPU frame-time checks apply to the Standard tier only; the heavier modes and the CPU-only path are measured and reported without failing the build.
  • Platform tests run the whole lens once on the software rasteriser to prove the CPU-only path gives the same picture.
  • A new theme cannot be merged unless it passes the full feature matrix.
  • Target for the first release: at least 150 scenario examples in Specs.

11Install and release

  • Main installer: a single ThemeLens-Setup.exe built with Velopack. One click, per user, no administrator prompt, no wizard pages. The app is published self-contained, so there is no separate .NET install.
  • Dark from the first pixel: the installer splash is a dark image with off-white text. The app's first window opens on black.
  • Updates: checked at startup, downloaded in the background as small delta packages, applied on next start. Can be switched off.
  • Other channels: a portable zip, and a winget manifest so winget install works.
  • Later: an MSI for organisations that deploy per machine, which is also the route to the uiAccess build; and a Microsoft Store listing.
  • Signing: unsigned installers trigger Windows SmartScreen warnings, which is a real barrier for this audience. Two routes: a free certificate through the SignPath Foundation programme for open-source projects (the publisher shown is SignPath Foundation, and the programme has its own conditions, so check them against the contributor agreement and any plan to sell commercial licences in section 12), or your own certificate, which costs money and shows your name.
  • Release pipeline: a tag on main triggers build, all tests, publish, pack, sign, and a GitHub Release with checksums.
  • Uninstall removes the app and the start-with-Windows entry and asks whether to keep user themes.

12.1Income routes

The GPL allows all of these.

  • A paid Microsoft Store build of the same code, for people who prefer Store installs. Other GPL desktop apps already do this.
  • Sponsorship through GitHub Sponsors or Open Collective.
  • Paid deployment and support for schools and employers who provide it as a workplace adjustment.
  • Commercial licences for organisations that cannot accept the GPL. This route depends on the contributor agreement.

12.2Dependency allow-list

Shipped dependencies: MIT, BSD-2-Clause, BSD-3-Clause, Apache-2.0, ISC, Zlib. These are generally accepted as compatible with GPL-3.0. Anything else needs a recorded decision, including GPL and LGPL libraries, because someone else's copyleft code would limit the commercial-licence route. CI generates THIRD-PARTY-NOTICES.md and fails on an unlisted licence.

Build tools are checked separately. For example, Inno Setup now asks commercial users to buy a licence, which is one reason the installer uses Velopack.
